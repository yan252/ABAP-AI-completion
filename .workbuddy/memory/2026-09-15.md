## 修复 Multi-Tab Query Handler Template 导入：renameInDir 文件名重命名 bug

**问题**：插件跑完显示 "Overall: OK"，但 SE38 找不到 ZTEST10。连接测试 `icf=error(404)` 不阻断成功（tls/auth/adt 必选层全 ok，icf 附加层，systems.json 中 icf.available=false）。

**根因**：`MultiTabTemplateImportService.renameInDir` 旧实现按"前缀 + 最后一段后缀"重拼文件名，破坏了 abapGit 双层后缀：
- `ztemplate10.prog.xml` → `ztest10.xml`（丢 `.prog`）
- `ztemplate10_cls.prog.xml` → `ztest10_cls.prog.xml.xml`（双重后缀）

导致 `collectByExt(".prog.xml")` 只找到未改名的 `ztr_show_jd.prog.xml`，主程序及 8 个 include 从未被 abap-cli 推送；步骤 4/6 因 mainXml 缺失返回 -1。

**修复**（`MultiTabTemplateImportService.java`）：
1. 新增 `renameObjectBaseInFileName(name, baseUpper, baseLower, newUpper, newLower)`，在文件名中**全量替换占位符**（大小写两形式），天然保留 `.prog.xml` / `.prog.abap`。
2. 在 `executeAll` 中加守卫：任何步骤 message 含 "not found"（改名/解压失败导致主程序 XML 缺失）→ `overall = -1`，避免假 "Overall: OK"。

**验证**：
- 全量 javac（--release 17，classpath = ~/.p2/pool/plugins/*）EXIT=0。
- Python 端到端复现解压+改名流程：16 个文件正确改名，9 个 `.prog.xml` + 9 个 `.prog.abap` 就绪，`mainXml=ztest10.prog.xml` 存在，`ztr_show_jd` 与 `package.devc.xml` 不受影响。

**待办/已知**：
- `ztr_show_jd` 的 `corrNr could not be found` 是独立已知问题（参考项目 abapgit 运行日志同样报错），不阻断 ZTEST10 主对象导入。
- 插件只按进程 exitValue() 判断成败，未解析扩展 JSON 里 `action: failed`；扩展内部对单对象失败通常仍 exit=0，后续可考虑增强（可选）。

## 排查"导入主程序类型 SUBC 错误"——结论：现状正确，用户理解方向相反

**用户报告**：导入后主程序类型不对，认为 `I`=可执行、`1`=INCLUDE，且"所有都成了 INCLUDE"。

**核对证据（全链路一致，结论正确）**：
1. 模板 ZIP（references/ZTEMPLATE10.zip）逐文件解包核对：`ztemplate10.prog.xml` → `<SUBC>1</SUBC>`（主程序），8 个 include + ztr_show_jd → `<SUBC>I</SUBC>`。文件里主程序**不是** `<SUBC>I</SUBC>`。
2. SAP PROGDIR-SUBC 域（代码注释亦确认）：`1`=可执行程序(REPT)、`I`=INCLUDE、M 模块池、S 子程序池、T 类型组、X 流逻辑。与用户理解（I=可执行、1=INCLUDE）**正好相反**。
3. prog-xml-create.mjs 映射表 SUBC_TO_ENDPOINT 支持 1/M/S/T/I/X 六类：1→PROG/P→POST /programs/programs；M/S/T/X→PROG/P（programs端点）；I→PROG/I→POST /programs/includes；未知 SUBC 抛错而非静默降级为 1。
4. 实际日志：_multi-tab_create_result.txt 显示 ZTEST10→SUBC=1 PROG/P（可执行）、8 include→SUBC=I PROG/I；source_push / verify 一致。插件改名步骤只替换占位符名，不碰 SUBC。

**结论**：模板、代码、实际导入结果三者一致且正确（主程序=可执行、include=INCLUDE）。用户观察到"全部 INCLUDE"与证据矛盾，大概率是：SE38 里看到的就是正确结果（ZTEST10=可执行），或用户记忆了旧版本/旧导入结果。已请用户贴 SE38 实际截图/说明而非改代码。若用户坚持要改（如把 I 当可执行），会破坏 SAP 标准并导致 include 写入错误端点——需先确认真实观察。
