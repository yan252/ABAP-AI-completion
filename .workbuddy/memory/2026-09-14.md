## 3. 修复 profile 解析 bug + 重新构建 1.0.8（连接测试报 Multiple profiles）
- 现象：dropins 安装后 SAP 连接测试报 "Multiple abap-cli profiles configured (S4DEV, auth, adtTextpool) … no 'system' field"。
- 根因：`AbapCliConnectionTester.readProfileNames()` 用正则 `"([A-Za-z0-9_\-]+)"\s*:\s*\{` 匹配 `~/.abap-cli/systems.json`，把 `systems` 下的嵌套子对象 `auth`、`adtTextpool` 误判为独立 profile。
- 修复：删除 PROFILE_KEY 正则，新增 JSON 感知轻量状态机 `topLevelKeysOfSystems(String)`：深度计数 + expectKey 标志，仅取 `"systems"` 对象第一层键；`case '{'` 时置 expectKey=true，收集后清空，字符串上仅 depth==1 时收集。已用 3 用例单测验证 PASS。
- **Git Bash 手动构建关键坑（上次记录不完整，本次踩通）**：
  1. p2 pool 中每个插件有多个版本，classpath 必须每插件取最新（`ls …_*.jar | sort -V | tail -1`），否则 118 个 jar 全塞入报"程序包不存在"。
  2. 直接 `javac -cp "a.jar;b.jar;…"` 在 Git Bash 会被 MSYS 重写分号分隔参数，传入无效。**必须用 @argfile**，且 argfile 内路径用 `cygpath -m`（正斜杠 D:/…），反斜杠会被 javac 当转义符吞掉（导致 `找不到文件: srccom…java`）；argfile 必须放 Windows 可解析路径（/tmp 会被转成 \tmp 而找不到）。
  3. 命令模板：`javac --release 17 -encoding UTF-8 -d bin -cp "<21个依赖jar;连接>" @D:/…/_javac_build_args.txt`（源文件列表也写入 argfile，每行带引号）。
- 产物：`dist/com.sap.abap.ai.completion_1.0.8.jar`（713,041 字节，77 class），javap 确认含 `readProfileNames` 与 `topLevelKeysOfSystems`、无 PROFILE_KEY。
- 部署：目标 `D:\Users\96000217\eclipse\dropins\`（dropins 里已有 10:52 旧版 1.0.8 jar = 不含修复的那版）。本次复制到 dropins 被沙盒拦截（D 盘个人目录），需用户在文件管理器中手动覆盖，然后 Eclipse 需重启（建议 -clean）。

## 4. 连接测试 diff 排查：succeeded 但 icf/capabilities=error 属正常
- 现象：测试弹窗显示 "succeeded"，但 Layers 里 icf=error、capabilities=error、ddlSourceSupported=error、exit=6；Eclipse error log 只有一条 INFO "[Auto-added missing system]"。
- 结论（非 bug）：插件成功判据 = tls+auth+adt 全 ok（AbapCliConnectionTester.REQUIRED_LAYERS）。log 仅在失败时写 ERROR，成功只在弹窗展示，因此 .log 只有 INFO 行属正常。
- icf=error 根因：abap-cli `profile test` 额外探测可选自建 ICF 服务 `/sap/zabap_vibe/`（handler ZCL_ABAP_VIBE_ICF，由 `abap deploy` 注册 SICF 节点），S4DEV 未部署 → SAP 返回 "Service cannot be reached" HTML（故 details 里有整页 html）。
- capabilities/ddlSourceSupported 显示 "error" 是 abap-cli 人读格式化的坑：无 `.ok` 字段的条目一律标 error（对象/布尔恒显示 error），非真实失败。
- exit=6 = worst failing layer（icf→6），非致命。
- 模板导入的 prog-* extensions 只用 ADT 端点（/sap/bc/adt/...），grep 确认不依赖 zabap_vibe，可安全忽略；如需测试全绿再 `abap deploy` 部署 zabap_vibe（需 SICF 管理权限 S_ICF_ADMIN）。
- 证据：`_abap-cli-stage/node_modules/abap-cli/dist/src/abap_cli/clients/probe.js`（probeIcf 第318行 path=/sap/zabap_vibe/；capabilities 探测第75-137行）、`flows/setup/profile.js`（worstExitCode/人读格式化）。

## 6. 答疑确认："S4DEV 从哪来" + "测试成功与否"（配置页 vs abap-cli profile 两套信息）
- 结论：**测试成功**。success 判据 = REQUIRED_LAYERS(tls/auth/adt) 全 ok（AbapCliConnectionTester.java 第49/150-155行）；弹窗"…succeeded."与配置页绿色 "SUCCESS: abapGit connection OK" 同处 r.success 分支，二者一致非矛盾。icf=error 是附加探测（zabap_vibe 未部署），capabilities/ddlSourceSupported=error 是 abap-cli 人读格式化对无 .ok 字段条目恒标 error；exit=6 仅 icf 层 worst exit code，非失败。
- **S4DEV 关键澄清**：不是来自 Eclipse 配置页！配置页(SapPreferencePage)填的是 JCo/RFC 信息（host/端口/client/user/密码/native lib），而测试按钮调用无参的 `AbapCliConnectionTester.testConnection()`，**完全不读配置页任何字段**。system 名由 `resolveSystemName()` 从 `~/.abap-cli/systems.json` 的 profile 列表 + stage `.abap.json` 的 system 字段解析；当前 systems.json 只有一个 profile=S4DEV（url/client/username/language/insecure/auth/adtTextpool/runtime），.abap.json system=S4DEV → 沿用。即：JCo 信息与 abap-cli 测试是**两套独立机制**，改配置页不会影响测试结果。
- 若用户想测别的系统：需在 abap-cli 侧 `init --profile <new>` 新增 profile 并设 .abap.json system（多 profile 时 .abap.json 无 system 会报"Multiple profiles"错，对应第4节修复）。

## 9. 复用经验（补记）
- **javac argfile**：`-classpath` 的值不能带引号——带引号会报 1495 个"找不到符号"；pool 路径无空格、分号非空白，作单个 token 安全。
- **p2 pool JRE**：javap/javac 位于 `<jre-full>/jre/bin/`（嵌套 jre 子目录，不是顶层 `bin/`），本机示例 `…jre.full.win32.x86_64_23.0.2.v20250131-0604/jre/bin/javap.exe`。
